IF SOMETHING DOESN'T WORK
═════════════════════════════════════════════════════════════════════════════

ERROR: "Cannot GET /vite/@vite/client"
───────────────────────────────────────────────────────────────────────────
Solution:
1. Ctrl+C in Terminal 2
2. rm -r node_modules
3. npm install
4. npm run dev
(Or: del /s node_modules, then npm install, then npm run dev on Windows)


ERROR: "Port 5173 already in use"
───────────────────────────────────────────────────────────────────────────
Solution 1:
1. Find what's using port 5173: netstat -ano | findstr :5173
2. Kill process: taskkill /PID <PID> /F

Solution 2:
1. Use different port: npm run dev -- --port 3000
2. Visit: http://localhost:3000/


ERROR: "Backend not running" or "No response"
───────────────────────────────────────────────────────────────────────────
Solution:
1. Check backend running: http://localhost:8000/health
2. If not running, start Terminal 1: python start_api_server.py
3. Wait for "✓ Server is ready!"
4. Refresh browser


ERROR: "No sessions found"
───────────────────────────────────────────────────────────────────────────
Solution:
1. Reload page: F5
2. Check browser console: F12 → Console tab
3. Look for [SESSION] logs
4. If no logs, backend not responding


ERROR: "TypeError: Cannot read property 'messages' of undefined"
───────────────────────────────────────────────────────────────────────────
Solution:
1. Clear browser cache: Ctrl+Shift+Delete
2. Close DevTools: F12
3. Reload: F5
4. Try again


ERROR: Messages not appending (each question separate)
───────────────────────────────────────────────────────────────────────────
Solution:
1. F12 → Network tab
2. Send message
3. Check POST /ask request:
   - Body contains "session_id": "sess_..."
   - Response is 200 OK
4. If not, restart both terminals
5. Check useChat.ts has sessionId parameter


ERROR: Sidebar empty (no sessions listed)
───────────────────────────────────────────────────────────────────────────
Solution:
1. Check browser console for [SESSION] logs
2. Verify /data/sessions/ directory exists
3. Check backend /sessions endpoint:
   curl http://localhost:8000/sessions?user_id=default_user
4. Should return JSON with sessions array
5. If not, backend issue
